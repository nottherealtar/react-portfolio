A fresh coding agent passed all four tasks against our framework docs. Here's what that result doesn't prove

So we moved the explanation into the package and then checked whether an agent that has never seen the framework source can work from it. Each project got a fresh agent (Sonnet) with a prompt that contained the environment, the task text and the rules: work only in the project, read only the project and its node_modules , no skills, no memory, no web search.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

Kumiko is our TypeScript framework for multi-tenant apps on Bun, Hono and Postgres. More and more of the code written against it comes from coding agents, and until last week those agents saw very little of it. The docs site exists, but it's outside what an agent sees in an app, and the instructions written for agents lived in skills inside our own workspace, so only our own sessions ever read them.

Since 0.364.0, @cosmicdrift/kumiko-framework contains an AGENTS.md , today about 350 lines. It explains the model (features, entities, handlers, screens, events, tenant scoping), lists rules in the form "never this, do that", and has a table of "I need X, use Y". Next to it sits an agents/ folder that the build generates from the source: an index of every bundled feature from the feature manifest, an index of every UI widget export, and one file per tested sample app with its README, source and tests.

A drift guard fails CI when the generated files no longer match the code. A new app from create-kumiko-app gets a short AGENTS.md of its own for other agents and a CLAUDE.md that imports the package file: The docs always match the installed version and work offline. Boot errors and guard messages also carry a docsUrl that points at a page for that error code.

We wrote four tasks of the kind a real app needs: A write handler and a query handler with integration tests (complete a task, count open tasks per tenant). An overview screen built from existing widgets. Mounting the bundled tags feature in an app.

Inside a workspace, bun resolves workspace links instead of the npm tarball, and the agent reads our source instead of the package. The prepare script refuses to run inside a directory that has a package.json or bun.lock above it. At the end it had to report in 15 lines what it built, which docs it read and what was missing.

A script copies a hidden acceptance test into the project that the agent never saw, then runs typecheck, lint, unit tests, boot validation, schema validation, the integration tests (the agent's own plus the hidden one) and our guards. It also scans the agent's diff for any , raw SQL writes, inline styles and a test helper we don't allow in integration tests. All eight checks passed in every project, including the hidden acceptance tests.

In task 2 the integration run had 13 tests: 8 written by the agent and 5 from the acceptance file. Every task still showed a gap in the docs: The boot errors did their job in task 1. The agent made the mistake, the error named the fix, and it applied it.

In the other three, the docs alone weren't enough, and the agents filled the gap by reading type declarations and compiled JavaScript in node_modules . For this eval we count it as a gap anyway, because the next agent might not look there. The task texts fixed names, payloads and IDs, so the hidden tests could find what they test.

Why this matters

A script copies a hidden acceptance test into the project that the agent never saw, then runs typecheck, lint, unit tests, boot validation, schema validation, the integration tests (the agent's own plus the hidden one) and our guards. It highlights where brittle integrations become operational debt as vendors iterate quickly.

Operational takeaways

  • The task texts fixed names, payloads and IDs, so the hidden tests could find what they test.
  • To save time, we started them as subagents from an existing Claude Code session instead of in a clean CLI with an empty config directory.
  • Only the columns for which docs an agent read and what it missed measure the package docs on their own.
