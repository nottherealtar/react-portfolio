Lambda Is No Longer Just One Function: 10 AWS Changes Before re:Invent 2026

AWS renamed it on October 12, 2026, and you probably haven't even heard about it. A Lambda function is now three things AWS says it plainly in an AWS Compute Blog post from November 19, 2026 : Lambda now has three form factors: Event Functions, Web Functions and MicroVMs. It's simply a way to run Event Functions on managed EC2 instances in your account, through a so-called capacity provider.

Over the past year AWS shipped plenty of updates for Lambda, API Gateway and EventBridge. We have new kinds of functions, a new event bus, and a few days ago the 15-minute limit many of us lived with for years went away. The phrase "Lambda function" no longer means one thing.

I've been writing about serverless on Serverless Polska, my Polish-language blog, since 2018. This isn't a tutorial, so you won't find code or configuration steps here. I want to sort out what Lambda functions are today and what to know before re:Invent 2026 brings the next wave of announcements.

Three changes get a deeper look and seven a shorter one, each with a date and a link to the AWS source. Event Functions are the good old functions we've known for years. They react to events and by default run on demand.

Existing functions don't need rewriting or redeploying. Your code listens on a port itself and handles HTTP requests, e.g. One environment handles many requests at once, and AWS describes the billing model as paying for active CPU time and for the environment's memory.

So waiting on a database or another service costs no CPU, but memory is still billed. For web apps and APIs that mostly wait for responses from other systems, I'd call this the most important change on the whole list. MicroVMs were announced by AWS on June 22, 2026 as a new serverless building block with VM-level isolation.

Each user or task gets a separate Firecracker-based environment with its own HTTPS address. State can be preserved, and the environment can be paused and resumed, capped at 8 hours of running and paused time combined. It's meant for running code written by users or generated by AI.

The environment handles many requests in parallel, and billing is based on EC2 pricing, including Savings Plans and Reserved Instances. There's a catch, though, noted in the AWS documentation : a 15% management fee is added to the instance price, and EC2 discounts cover only the instance itself. Since March 27, 2026 , functions on Managed Instances can have up to 32 GB of memory and 16 vCPUs (up from 10 GB).

There are also durable functions , which I cover later on. A web app or API that mostly waits on the database? Code you don't trust, because a user or an AI model wrote it?
