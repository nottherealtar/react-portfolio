Rider 2026.3 for Game Development: Lua and Verse Plugins, Better C++ Debugging, and Closer Godot Integration

This release connects Rider more closely with the Godot Editor, improves debugging for Unreal Engine and custom C++ engines, adds support for Unity CoreCLR Players, and introduces new Lua and Verse plugins in Beta. For a lighter, Verse-focused setup, open the generated .code-workspace file.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

Rider 2026.3 brings improvements to the workflows you rely on to write, run, and debug games. The plugin supports Lua 5.1–5.4, LuaJIT, and Luau, with: Code completion, documentation, parameter information, and inlay hints. Navigation, Find Usages , call hierarchy, and require path resolution.

Refactorings such as Rename , Extract Function , Inline , and Change Signature . It also understands existing EmmyLua, LuaLS, and LDoc comments, as well as Luau type annotations, so you can keep the annotations your project already uses. The new Verse Language plugin uses Rider’s own language engine to offer Verse support without requiring an external language server.

It provides syntax highlighting, error detection, code completion, navigation, Find Usages , and Quick Documentation . These capabilities are also available to AI agents through Rider’s MCP server. The plugin is available in Beta through JetBrains Marketplace.

Cross-language navigation between C++ and Verse is not yet supported. Command-line argument presets: Keep your launch scenarios ready With different maps, log levels, and test flags, you often have to run the same game with different arguments. Rider’s built-in command-line argument presets replace the EzArgs plugin .

Create a shared list of arguments, organize them into presets, and choose a preset from the main toolbar before running or debugging. Presets are independent of run configurations, so you can reuse the same arguments across Debug and Release builds. Arguments support types and validation, and you can toggle individual arguments or entire folders.

Already have a command line saved in EzArgs or elsewhere? Paste it into Import Args from Command Line to split it into arguments and detect their types automatically. You can share presets through version control or move them between projects using XML import and export.

Godot: Bring your editor, code, and scene together Rider and the Godot Editor now have a live connection, making it easier to switch between your code and the scene you’re building. You can debug the current scene in C# or GDScript. If you use C#, the scene launches through the Godot Editor with Rider’s debugger attached from the first frame.

You can use Godot’s embedded game window to pause execution or adjust game speed while Rider handles your breakpoints. You can also right-click a file in either application to open it in the other. To enable the connection, install and enable the JetBrains Rider Integration add-on from the Godot Asset Store.
