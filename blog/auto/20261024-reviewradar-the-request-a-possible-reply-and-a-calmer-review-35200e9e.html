This is a submission for the Hacktoberfest Open-Source AI Challenge Week 3: Slow and Steady . A review can ask for a screenshot in one place, describe a bug in another, and receive an author reply several days later. A PR status compresses that conversation into a label.

The small chore I wanted to address was finding the original ask again and reading it beside the relevant reply. ReviewRadar is a local evidence workbench for selected public PRs you authored. Gemma identifies individual human-reviewer requests and proposes relevant later author responses.

The app places those original passages beside each other, with their dates and GitHub links. You inspect the context, keep a local note, and decide what deserves another look. It is for the contributor returning to several review conversations after a break: not “write my reply,” but “show me the ask and the context I need before I reply.” The intended saving is repeated searching and rereading.

Whether the model's preparation and correction cost makes that worthwhile still needs a genuine-user test. The input came from my actual open-source contribution history. A later author update reported adding screenshots .

That pair is more useful to read together than as two disconnected notifications. It still does not establish that the screenshots were sufficient or that a maintainer was satisfied. There are three separate states throughout the interface: What GitHub reported when the snapshot was fetched: PR/review/thread state.

What the model suggests: a request and a possible conversational response. What I decided locally: reviewed, reopened, or a note for later inspection. No button comments on GitHub, resolves a thread or marks code correct.

That boundary keeps a reading aid from quietly becoming an authority over someone else's review. It shows three real request/response examples in the same workbench used by the local app. Its analysis was generated by an actual local API run and saved; opening the page does not run a model or import your GitHub account.

Review choices in the replay stay in that browser and can be reset. Try one concrete task in the replay: Open the Eventyay screenshots request. The model has not inspected the screenshots or established maintainer satisfaction.
