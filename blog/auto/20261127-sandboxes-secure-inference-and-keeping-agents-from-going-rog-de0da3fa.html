Ivan Burazin: Thank you so much for having me. Ryan Donovan: So this breaking-out-of-the-sandbox idea has been very much in the news with the Hugging Face attack. So I mean, it was all over the news, and rightfully so that people are interested in this.

Just one step before I get to that — the sense of the term "sandbox." We at Daytona are a sandbox vendor, as are many other companies. That being said, sandboxes are both what we like to say "computers for agents" — an actual tool for agents to get things done — but also at the same time, a place where you sort of lock down the agent from other things, hence the name sandbox. I mean, it could be a container, it could be a VM, it could be a bare metal machine.

The vast majority are virtual machines, or micro-VMs to be more specific. Others, like us, the purpose is to give the agent tools and be as performant as possible. Of course, security is table stakes, but there are different levels to security.

One: if you have an agent that has the capability to escape and has no guardrails, it would make sense that you would first put the same model and/or agent with guardrails to test it out. I understood it to be deliberately lowered security. They were doing an exploit benchmark test and they gave it an impossible task.

And then, in that case, it should be no surprise that they did it, right? It should be like, oh, it actually did it — great, fine, done. Maybe they could have picked somewhere else, I mean, this was benign, even the break-in of Hugging Face, but they could have picked a random place that they had set up themselves so they didn't go to third parties.
