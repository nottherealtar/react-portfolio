KubeCon NA 2026 Live: The Identity Crisis of AI Agents and the First Announcements from Salt Lake City

The identity crisis of agents, the integration of MCP into platforms like OpenShift, and the packaged management of agent skills are not fringe topics but the central construction sites for 2027. The coming months will show whether the outlined solution approaches — per-instance identities, versioned skills, and platform-agnostic AI gateways — prove themselves in practice.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

KubeCon + CloudNativeCon North America 2026 opened on November 9 in Salt Lake City — and the first half of the conference has already made it clear that this year is not just about GPU scheduling and inference frameworks. The organizing question running through keynotes, side events, and announcements is more fundamental: How can we even trace which AI agent performed which action in a Kubernetes cluster? The SPIFFE standard and its reference implementation SPIRE assign cryptographic identities to workloads in Kubernetes via service…

This works excellently for classic workloads like database pods or API gateways, where each instance is functionally identical. However, this model breaks down with AI agents. An agent that has accumulated tool calls, retrieval results, and intermediate conclusions over six hours in a conversation context is not identical to a freshly started agent — even if both use the same container image and the same service account.

An analysis by Solo.io from August 2026 described the gap as a "fundamental contradiction between the non-deterministic, context-dependent behavior of agents and the rigid identity assignment via infrastructure topologies." The numbers underscore the urgency: According to the NHI Management Group, 72 percent of organizations now have more non-human than human identities in their environments. Teleport found that 70 percent of companies grant AI systems more access than humans in comparable roles. Various solution approaches are…

A consensus has not yet been reached — discussions in the working groups are ongoing. Red Hat OpenShift 5.0: Built-in MCP Server Red Hat used KubeCon to introduce OpenShift 5.0 — a platform designed for the era of agentic AI. The core of the announcement: OpenShift receives an integrated Model Context Protocol (MCP) server, allowing AI agents to directly access cluster resources without separate middleware.

In parallel, Lightspeed has been extended with an AI agent through which IT teams can orchestrate multiple models to automate workflows. Additionally, there is OpenShell, a sandbox environment for OpenClaw agents developed by NVIDIA and integrated by Red Hat. The architecture isolates agents in shielded runtime environments — an architectural pattern that other vendors are also adopting.

Cloudsmith: Agent Skills as Versioned Packages Cloudsmith presented an AI Agent Skills Registry at KubeCon. Behind it lies a simple but powerful idea: The capabilities of AI agents (skills), consisting of a SKILL.md file plus scripts, references, and templates, are versioned, reviewed, and distributed like software artifacts. "Community skill registries were built for sharing, not for control," said Alison Sickelka, VP of Product at Cloudsmith.

"With Cloudsmith, platform teams decide which skills and versions are allowed, block the unwanted ones, and see every pull in the same audit trail as the rest of their software supply chain." This closes a gap that is becoming increasingly urgent with the growing prevalence of AI coding agents: An unchecked skill can change what an agent does — and skills from public catalogs carry the same unknowns as any open-source dependency. "Customers rarely buy a gateway for its own sake," said Sudeep Goswami, CEO of Traefik Labs. "They choose a platform for their infrastructure — and expect the controls to work there." The first half of KubeCon NA 2026 shows a clear trend: The cloud-native community has built the infrastructure for AI workloads — now it's about control, traceability, and security. Anyone operating Kubernetes for AI agents should closely follow the discussions from Salt Lake City.

It is a useful datapoint for how AI-assisted engineering and operations are converging in production.
