Your Coding Agent Is a Key Vault You Never Audited. The OpenCode Breach Proves It

On the morning of October 17, a subset of OpenCode Console users opened an email with the subject line "Action Required: Potential provider key breach." The key sentence inside: "Third party provider keys (for example OpenAI, Anthropic) saved in your workspace may have been exposed.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

Security researcher Matt Johansen had already posted the now-viral summary: "Confirmed. Telling customers to revoke." If you use any AI coding tool that asks you to paste in your own API keys, and most of them do, this breach is about you even if you never touched OpenCode. Not because of the specific vulnerability, which is still under investigation, but because of what the design itself makes inevitable: every "bring your own key" agent is a credential vault, and you have probably never audited what is inside yours.

Here is the timeline, assembled from OpenCode's public statements, the customer email shared in the Hacker News thread, and reporting from security researchers. An unauthorized party accessed a legacy OpenCode Console system that was, according to the customer email, "in the process of decommissioning." That system contained API keys users had saved in their Console workspaces to connect the coding agent to external providers like OpenAI, Anthropic, and Google. OpenCode emailed affected users, urging them to revoke and replace their…

Matt Johansen posted that OpenCode customers were receiving breach notices and that people were DMing him about API keys "running up charges." 18:08 UTC. OpenCode publicly confirmed the breach on X, calling it a "large scale distillation attack" affecting 1.4% of Console users, and said it was working with Anthropic, OpenAI, and Google on remediation. How the attacker got in, how long access lasted, how many keys were actually taken, and whether every exposed key was misused.

OpenCode has declined further technical details because the incident is ongoing. The scope was narrow, and OpenCode has been clear about that: only Console users who had linked external providers were in the affected group, and anyone who did not receive the email was not impacted. Anthropic, according to a post shared in the coverage, proactively revoked some Claude API keys it believed were affected.

But narrow scope does not change the shape of the problem. The affected population was precisely the group that followed the intended workflow: link your provider key in the dashboard so the agent can bill your own account. The convenience feature was the attack surface.

Distillation changes what a stolen key is worth The strangest word in OpenCode's statement is "distillation," and it matters more than the dollar amounts. Distillation, as Anthropic defines it in its own writing, is training a less capable model on the outputs of a stronger one. It is one of the main ways smaller labs catch up to frontier models.

The catch is that you need massive volumes of frontier model output, and generating that output normally costs enormous amounts of money. A stolen provider key is not just a wallet to drain. It is free access to frontier model output at someone else's expense.

The reports from affected users fit this pattern: charges run up dramatically in a short window, with one reported at around $400 and another reportedly exceeding $1,700 before the keys were disabled. That spending pattern looks less like someone joyriding on your account and more like industrial-scale data collection. If keys were only being stolen to run a few extra queries, spend caps would mostly solve the problem.
