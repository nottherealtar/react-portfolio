The Local Loop Is the Architecture

An agent is not a service with a prompt bolted on. That boundary will not appear in production. The thing they can share is a protocol at the edge of the privileged resource, and a loop that runs all three processes where a human can still watch a retry happen.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

We spent a decade teaching systems to cross a network. We are about to spend the next one teaching them not to. Put two of those runtimes in different languages — a legal graph in Python, a commercial node in TypeScript — and the interesting design problem is no longer which model you picked.

It is which process is allowed to touch the ledger, and how the other processes are prevented from growing their own path to it. That boundary will not appear in production. By then each team will have a client, a secret, and a story about retries.

It has to appear on the laptop, while both agents are still being rewritten every afternoon. For this class of system, it is the architecture. Compose files, port maps, a README that lied about the order of docker compose up .

Painful, and solvable, because the processes were passive. A worker did not invent a new call while you were looking at a trace. The Python node and the TypeScript node can both "check the budget" and mean different things: one reads a view, one posts a reservation, one retries the post because its HTTP client timed out after the database had already committed.

Two arrows into the ledger is already a distributed system. The model vendors will not design it for you. Neither will a framework that only knows one language.

Mastra does not owe LangGraph a session model. LangGraph does not owe your Next.js app a type. The gateway is the only component that can turn a tool call into a query, and the only component that is allowed to remember that a given attempt already happened.

A schema that says departmentId: string does not stop a second write. What stops the second write is a process that refuses to be a tunnel: closed arguments, named operations, an attempt id stored beside the row. The frontier move is not "expose the ERP over MCP." That is how you launder a database into every agent.

The move is to publish capabilities , and to make the capability smaller than the fear. check_department_budget can be backed by a view, a procedure, or a fixture. The agent cannot tell, and should not be able to.

Why this matters

It is a runtime that can decide, retry, and call a tool whose effect outlives the call. It matters for compliance and go-to-market planning when the rules of the road for tech are still unsettled.

Operational takeaways

  • The local loop is not a staging copy of the architecture.
  • Two arrows into the ledger is already a distributed system.
  • Three properties fall out of putting the tool in a process that is not an agent.
