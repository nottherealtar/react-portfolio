What’s fixed in IntelliJ IDEA 2026.3

IntelliJ IDEA 2026.3 ships over 1,000 bug fixes and over 300 performance fixes . Among others, Spring Boot inlay hints , property highlighting , and JPA entity analysis no longer stall the editor. We removed excessive index updates when a second project closes during indexing and made the workspace model copy files lazily .

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

Welcome to an overview of the most important fixes and usability improvements in IntelliJ IDEA 2026.3. We focused on performance, Java and Kotlin code intelligence, and the core workflows that matter for both classic and agentic development. User reports and data shared through automatic submission drive most of this work.

Below is a recap of the most impactful updates. Freezes, CPU usage, and memory were the focus of this release. Many of these fixes came from freeze reports and profiling of real projects, and others came from your tickets.

We removed UI freezes in the places where they were reported most often. Tomcat, WildFly, and JBoss no longer read configuration files on the UI thread . The same goes for the debugger’s variable building , the Git Commit and Changes trees , Optimize Imports , and Java SDK setup.

Launching the IDE no longer starts WSL when you do not need it. A code lens preview no longer keeps HiDPI images alive on the heap , and the JPA model no longer creates a new cache key on every lookup . Several leaks that kept closed projects in memory are fixed.

Importing large Maven and Gradle projects got optimization fixes. A deadlock during import on a remote development host is gone. A five-minute import of the Kotlin repository with Gradle 9.7 no longer spends most of its time processing errors after Gradle has finished.

Automatic error and freeze reporting To find the problems that interrupt your work and fix them in order of impact, IntelliJ IDEA 2026.3 sends error and UI freeze reports to JetBrains automatically. File paths, URLs, and usernames are removed before anything leaves your machine. You can turn reporting off in Settings | Appearance & Behavior | System Settings | Data Sharing .

JaCoCo is now the default coverage runner for new Java run configurations. It is the runner Gradle, Maven, CI systems, and SonarQube already use, so coverage numbers in the IDE match the ones in your pipeline. The Unused declaration inspection now reports methods that are used only from test sources .

Quick fixes for the “might be null” inspection work on complex expressions, Rename stops suggesting the current name , and generic stream-to-list conversions no longer show a false compilation error. A new inspection warns when CancellationException is caught in suspending code and not rethrown , and offers a quick fix. Blocking calls are highlighted in suspend lambdas , and converting Java to Kotlin now turns @lombok.Data classes into data classes .
