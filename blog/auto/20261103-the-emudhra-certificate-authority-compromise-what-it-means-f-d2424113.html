The eMudhra Certificate Authority Compromise: What It Means for TeamCity

Starting with versions 2026.2.2 and 2026.1.6 , TeamCity shows a health report if the installation still trusts affected certificates, along with remediation steps. JetBrains patches TeamCity Cloud, but certificates uploaded to the service still require review. Update your TeamCity agents and review trusted certificates Update Java on every build agent.

Key details from the source

Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

In October 2026, the private keys of eight intermediate certificate authorities operated by eMudhra were found to be weak and recoverable from public data. According to eMudhra’s official statement , none of the affected intermediate CAs had issued end-entity (leaf) certificates , and eMudhra is not aware of evidence that the weak keys were recovered or exploited before the issue was disclosed. The issue is not a vulnerability in TeamCity itself.

However, the trust stores maintained by other software components (primarily the Java runtime) that TeamCity relies on may continue to trust the compromised certificates. Upgrade to v2026.2.2 or v2026.1.6 for an updated Java runtime for the Windows agent installer, updated Docker images, and the health report, or follow the instructions below to apply the same fixes to the current installation. TeamCity Cloud: TeamCity Cloud has already been updated.

Certificates uploaded to TeamCity must be reviewed as described in Certificates uploaded to TeamCity below. Self-hosted build agents must also be reviewed according to the instructions below. On October 17, 2026, the private keys of eight eMudhra intermediate CAs, six for TLS and two for code signing, were reported as compromised.

This is an industry-wide certificate authority incident, not an issue specific to TeamCity. Certificates issued with these keys would look valid to any software that still trusts them. Browser and OS vendors have released updates that block the compromised certificates, and systems are protected once they install them.

Software with its own trust store, such as a Java runtime, keeps trusting the compromised certificates until that trust store is updated. TeamCity downloads are not signed by an eMudhra CA and are not affected. Identify the Java runtime used by each server node and agent, including any custom trust store set with javax.net.ssl.trustStore .

Check the Java vendor’s release notes for CVE-2026-91403 and CVE-2026-114820 . For Amazon Corretto 21, the fixed build is 21.0.13.0.11 or later. Update affected runtimes and restart each server node or agent.

Optional trust-store verification can identify affected certificates still present in a trust store. If upgrading is not feasible, follow the manual mitigation commands in the same section. Removing AAA Certificate Services can disrupt unaffected services; test dependent connections before removing that root.

Existing agents require an independent review. Use the health report or the certificate inspection commands below and then remove affected certificates through the Root project’s SSL / HTTPS Certificates page . Updating Java does not remove uploaded certificates.
