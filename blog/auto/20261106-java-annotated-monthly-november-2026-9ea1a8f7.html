Piotr Przybył – Notorious engineer at work and after hours, tracing the meanders of the art of software engineering.

Remote Software Gardener, mostly working in web-oriented Java gardens. Programming usually in Java (since 1.3), Scala, and Go, but in other languages too. Fan of agility, seen mostly as choosing the right tools and approaches after asking the right questions.

Developer, trainer, and conference speaker, currently working at Elastic as a Senior Developer Advocate. It’s a pleasure to be here again – it’s been three Java releases since the last time. We all know that means roughly 18 months, don’t we?

;-) Both the world and our ecosystem were moving fast back then, and it seems they have only accelerated. This means one thing: good luck trying to keep up to date with everything. Luckily for us all, newsletters like this one help.

The autumn conference season of 2026 is slowing down. It was a busy and exciting one, for me in particular, because Java 28 is already shaping up. And if you look at the list of JEPs already there, how can you not be excited?

Structured Concurrency is set to become final in March 2027, yay! Bye-bye, CompletableFuture, it was fun knowing you… not ;-). CF isn’t going anywhere, but it won’t be the best abstraction for concurrent subtasks.

Apart from that, there’s going to be one less thing for me to rant about, because Java is going to have (for now as an incubator module) a Simple JSON API. If your microservice only has to send one simple REST request with a JSON body, maybe this plus the JDK’s HTTP client will be enough? There are going to be improvements to GCs and more performance goodies, but my personal favourite is going to be Value Objects, because 42 is always 42, and it shouldn’t need an identity crisis to answer everything.

The need for this improvement is already here, because AI, like it or not, also means exchanging an awful lot of tokens and vectors.
