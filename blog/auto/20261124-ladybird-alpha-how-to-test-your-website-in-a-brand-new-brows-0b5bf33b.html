Editorial digest: additional context drawn from the original reporting. Open the primary source for quotes, figures, and updates.

On November 23, 2026, the Ladybird team published Ladybird is now in alpha . The first public build, version 2026.47.7, is out for macOS and Linux. The engine is our own, built from the ground up, and not a fork." That last part matters for web developers.

Almost every browser you test today runs on Blink (Chrome, Edge, Brave, Opera), WebKit (Safari) or Gecko (Firefox). The GitHub release notes say Ladybird "isn't a fork or a wrapper around Chromium, WebKit or Gecko. HTML, CSS, the DOM, layout, JavaScript and WebAssembly are all implemented from scratch." So when your site breaks in Ladybird, it is breaking in an engine your site has probably never been tested against.

It supports WebDriver for automated testing, as well as the Firefox DevTools protocol." This guide covers four steps: install it safely, inspect your pages, automate a check, and send a useful report. It is built from the project's release notes, docs and source code, not from hands-on testing. Version: Alpha 2026.47.7, dated November 23, 2026.

macOS: needs macOS 14.4 or later on Apple silicon. Flatpak (a Linux app format that works across distributions) is the recommended install. There are also APT packages for Ubuntu 24.04 and 26.04+, an RPM repo for Fedora 44 and 45, and a standalone archive.

Updates: the alpha is "a rolling channel, and we'll be pushing out automatic updates regularly." Rolling means new builds keep arriving, instead of a few big versions a year. The standalone archive is the exception; the page says it "doesn't update automatically." The Hacker News thread on the launch passed 1,500 points and 340 comments in its first 11 hours. One commenter posted the user agent string the macOS build sends, which matters in Step 5.

Ladybird's process isolation "is still being hardened: The browser process and the other helper processes don't yet treat every request from the WebContent process as untrusted." WebContent is the sandboxed process that runs web pages. For a testing machine, that leads to three simple rules: Do not log in to real accounts. Use test accounts on staging, not your production admin login.

Do not browse to internal dashboards that hold API keys or customer data. Prefer a separate machine, VM or user account if you plan to use it for more than a quick look. The download page gives a verification step for every package.
