Six months ago, finding a Claude agent skill meant opening fourteen GitHub tabs. You'd start at Anthropic's own repository, then follow a link from someone's post to a community fork, then another fork of that fork. And every one of them lived in a different folder structure, so you couldn't tell what a skill did without reading its SKILL.md line by line.

Over a thousand skills, pulled from Anthropic's public repositories and the largest community collections, then classified, described, and made downloadable from one page. Most skills solve five problems, not a thousand The long tail is real, but it is thinner than the raw count suggests. Reading, generating and editing .docx, .pdf, .xlsx, .pptx.

It is also the category where skills matter most, because these are formats where a model without procedural guidance produces output that is technically valid and visually broken. Conventions, review checklists, framework-specific patterns. Skills here encode a team's taste, not a capability.

Wrappers and protocols around APIs, most of them now converging on MCP. Marketing copy, changelogs, release notes, documentation. If you are writing your first skill, you are almost certainly writing one of these five.

Too narrow, and the skill never fires: Too broad, and it fires on everything, crowding out skills that actually apply: The ones that work name the trigger conditions explicitly: the file extensions, the verbs, the phrasings a user would actually type. Telling the model when not to load a skill is as valuable as telling it when to. Those are consistently the better-behaved ones.

Bundled scripts beat prose instructions There are two ways to write a skill that manipulates files. You can describe the procedure in prose and hope the model reconstructs the code correctly each time. Or you can ship a working script alongside the skill and have the instructions point at it.

The second approach wins on every axis that matters. It is deterministic, because the same script runs the same way every time. It consumes fewer tokens, because the model reads a one-line invocation instead of a forty-line explanation.

And it is debuggable by a human, because the script is just a file you can run yourself. A short SKILL.md that establishes when to act and what the constraints are, plus a scripts directory doing the actual work. The worst are three thousand words of prose trying to talk a model through something a twenty-line Python file would handle exactly.
